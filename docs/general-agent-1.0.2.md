# 범용 화면 에이전트 개선 — 1.0.2

## 의도와 구조

안내 종료, 주유소 탐색, 경로 비교, 경유, 제보, 목적지 수정은 필요한 범용성을 설명하는 예시다.
예시마다 실행 함수를 추가하거나, 목록 밖의 요청을 지원하지 않는 구조로 만들지 않는다.
빠른 Android API/Intent/Deep Link나 기억한 경로가 전체 요청을 해결하지 못하면,
원문 목표를 공통 화면 AI에 전달하여 실제 화면 관찰과 조작을 이어간다.

AI에는 앱별 기능 enum 대신 앱 열기·클릭·길게 누르기·입력·상하좌우 스크롤·상세 관찰·뒤로가기·대기와
완료/질문/실패 판단을 제공한다. 화면의 실제 번호만 사용할 수 있으며, 계산 중 바뀐 조작 대상은 다시 확인한다.
새 기능은 화면의 메뉴·검색·상세 내용에서 찾는다. 실제로 구분할 수 없는 후보나 사용자만 제공할 수 있는 정보가 있을 때 질문한다.

| 정보 요청의 답변을 검증기에 전달하지 않음 | 계산 결과가 앱 화면에도 표시되어야 한다고 오판 | 답변 후보를 관찰 값과 대조하도록 전달 |
| 실행 후 실제 결과를 검증 답변으로 전달하지 않음 | 재생이 시작됐는데도 미완료라고 판단하고 일시정지를 시도 | 실제 결과 문구와 변경 상태를 완료 검증에 함께 전달, 완료 후 추가 조작을 회귀 검사 |
| 옵션 화면에 체크 항목이 나타나기만 해도 검증 | 설정 변경 전 불필요한 검증과 잘못된 완료 후보 생성 | 새 항목의 등장과 실제 체크·선택 변경을 구분 |
| 이력에 '화면 바뀜'만 있고 적용 전후 값 없음 | 이미 적용된 선택·스위치를 미완료로 오판 | 실제 전후 상태 변화와 현재 적용 값을 명시 |

| 완료 근거의 화면 번호·값을 생성하며 오류 | 실제로 실행했어도 틀린 번호로 검증 실패하거나 없는 값을 근거로 성공 주장 | 현재 관찰과 실제 변경 이력에서만 완료 근거를 선택하도록 출력 문법 제한, 별도 대조 |
| 근거 문장을 길게 다시 생성 | 검증 한 번이 30초 추론 제한을 넘어 실패 | 실제 값은 앱이 보관하고 모델은 짧은 근거 참조만 반환 |
| 실패한 시도와 실제 실행을 검증기에 같이 전달 | 실행되지 않은 동작을 했다고 추정하며 결과 오판 | 다음 행동 판단에는 실패를 유지하고, 검증에는 실제 변경 근거를 전달 |
| 실제 실행 이력을 참조로 주면서 본문에는 '지금까지 없음' 표시 | 서로 모순되는 검증 문맥 | 없는 이력 표시를 제거하고 실제 변경 근거와 사라진 제어의 이름·현재 부재를 명시 |
| 미선택 상태는 표시하지 않고 선택됨만 표시 | 미선택 탭을 진행 중 기능으로 오해 | 현재 제어의 실제 선택·체크 값을 true/false로 명시 |
| 상세 제목을 후속 실행의 결과로 사용 | 실행 버튼을 누르기 전에 여러 단계 완료로 오판 | 요청한 실행 제어가 미실행이면 제목만으로 완료 근거를 인정하지 않음 |
| 실제 종료 뒤 검증 모델이 다음 행동을 다시 계획 | 정상 화면으로 돌아와도 다른 버튼을 누르며 반복 | AI가 최종 동작으로 고른 실제 종료의 공통 후조건 검사. 복합·조건부 요청은 제외 |
| 요청한 옵션 대신 기존 옵션이 선택되어 있어도 완료 가능 | 선택 화면만 열고 적용했다고 응답 | 요청한 실제 옵션과 현재 선택 상태의 충돌 검사 |
| 설명부터 생성하며 같은 판단 반복 | 화면이 바뀌어도 이전 설명을 반복 | 동작을 먼저 선택하고 예상·설명을 생성 |
| 상세 관찰이 새 정보를 주지 않아도 반복 가능 | 실제 조작 없이 모델 호출만 계속됨 | 새 정보 없는 관찰도 진행 없음으로 계산 |

`expect`는 앞으로 확인할 변화이며 증거가 아니다. 모델이 `check=true`로 최종 행동을 예상해도,
실제 결과와 전체 조건이 확인되지 않으면 다음 동작을 계속 판단한다.
메뉴 열기·검색 제출·후보 선택만 끝난 상태는 여러 단계 요청의 완료가 아니다.
일반적인 클릭 뒤에도 목표 관련 실제 결과가 새로 관찰되면 전체 목표를 검증한다.
정보 요청에서는 실제 값과 비교 결과를 사용자에게 전달하며, 결과 문장을 일반적인 '완료'로 줄이지 않는다.
검증 모델의 성공 응답에는 실제 선택/체크 상태·내용·실행 이력의 근거가 필요하다.
근거 후보는 매번 현재 관찰에서 생성하며, 존재하지 않는 화면 번호나 계산 결과를 UI 값으로 만들어 낼 수 없다.
`s번호`는 현재 화면의 실제 값, `h번호`는 실제 변화가 확인된 실행 이력을 참조한다.
모델이 같은 값을 길게 재생성할 필요 없이 이 참조를 선택하며, 앱에서 다시 유효성을 확인한다.
선택할 수 있는 근거가 실제로 존재한다는 것만으로 전체 목표가 완료되는 것은 아니므로,
목표의 모든 조건을 충족했는지는 여전히 모델이 판단하고 결과를 재검사한다.

명확한 단일 종료 요청에는 공통 완료 후조건이 있다. AI가 실제 화면에서 종료 동작을 고르면,
실제 화면 변경·종료 제어 부재·진행 내용 부재·확인 대화상자 부재를 검사한다.
메뉴 닫기·탭 전환·뒤로가기는 이 종료 후조건을 충족하지 않는다. 남은 작업·유지 조건·예약 시간이 있는
요청은 이 빠른 판정을 사용하지 않으며, 전체 목표를 계속 검증한다. 앱 이름이나 기능별 실행 순서를 등록하는 규칙이 아니다.

## 검증 범위

JVM 회귀 검사는 빠른 경로의 범위, 복합 목표 보존, 모호한 후보 질문, 관찰 값 유지,
화면에 없는 대상 노출을 위한 상세 관찰, 가로 스크롤, 실제 상태 변경, 중간 버튼의 완료 오판,
새 정보 없는 반복 제한을 확인한다.

실제 선택된 Kanana 모델의 Android 검사는 사전 등록된 장소·레시피·기능 도구 없이 모의 앱 화면을 사용한다.
예시 작업은 특정 기능의 지원 목록이 아니라 공통 루프의 검증 사례다.
메뉴를 통한 임의 앱 설정 변경, 기존 선택을 유지한 정보 비교, 조건에 맞는 후보 비교 후 후속 실행,
진행 작업을 유지한 옵션 변경과 이전의 임의 앱 종료·검색 후 재생·내비 종료 회귀를 검사한다.
실제 모델 검사에서 발견한 완료 누락과 중간 단계 오판은 위 공통 경로의 수정 근거다.

검색 후 재생 검사는 최종 화면뿐 아니라 재생 뒤 일시정지 버튼을 누르려고 했는지도 확인한다.
최종 상태가 우연히 유지되더라도 완료 후 반대 동작을 시도하면 실패한다.
종료 검사에서도 일반 화면으로 돌아간 뒤 추가 조작을 시도하면 실패한다.
별도 캐시 검사는 같은 입력·출력을 CPU와 GPU에서 각각 사용한다. 다른 역할의 추론을 사이에 실행한 뒤
행동 문맥의 토큰 재사용이 유지되는지도 확인한다. CPU 검사 후 기존 GPU 설정을 복원한다.

최종 검사 결과와 정확한 환경·시간은 릴리즈의 `validation.json`에 기록한다.
모의 화면 검사 통과를 실제 NAVER Map의 모든 기능이나 물리적 음성/뒷면 호출의 검증으로 표현하지 않는다.
1.0.1의 실제 지도 결과는 [이전 진단 보고서](navigation-diagnosis-1.0.1.md)에 별도로 보존한다.

## 현재 한계

전체 목표를 제한 없는 실행 경로로 보내는 것과 로컬 모델이 모든 요청을 정확히 수행하는 것은 별개다.
작은 모델의 조건 해석·산술·탐색·종료 판단 오류, 앱의 접근성 정보 부족, 권한/잠금, 화면 로딩은 여전히 실패 원인이 된다.
성공하지 못했거나 완료 근거가 부족하면 실패 또는 질문으로 보고하며 성공한 것으로 저장하지 않는다.
여러 화면을 거치는 작업은 모델을 여러 번 호출하므로 음성 인식 후 10초 목표를 아직 보장하지 않는다.
실제 제품 화면에서 각 작업의 정확도와 시간을 추가 검증해야 한다.

## S25 실측

S25 Ultra(SM-S938N)의 선택된 Kanana 1.5 2.1B Q4_K_M, 6 threads, context 3072를 사용했다.
같은 926-token 입력과 같은 고정 JSON 출력을 CPU/GPU에서 각각 처음·재사용 상태로 검사했다.
두 추론 사이에 완료 검증 문맥을 사용해도 행동 문맥의 925개 토큰이 유지됐다. 모델 가중치는 한 번만 적재한다.

| 비교 | CPU | GPU |
|---|---:|---:|
| 모델 적재 | 3.16초 | 4.25초 |
| 처음 추론, 적재 제외 | 24.01초 | 18.86초 |
| 다른 역할 추론 뒤 행동 캐시 재사용 | 3.75초 | 10.30초 |

각 백엔드의 두 번 측정으로, 속도 순위나 항상 일정한 지연을 보장하는 수치는 아니다.
실제 출력 문자열은 같지만 토큰 분할은 CPU 37개/GPU 51개였다. 이 결과로 GPU 계산 오류를 단정하지 않는다.
기존 GPU 설정과 선택 모델은 유지한다.

CPU에서 실제 모델과 모의 화면을 사용하는 Android 회귀 검사 11개가 통과했다.
새 범용 사례의 실행 시간은 설정 변경 54.6초, 선택 유지·시간 비교 18.5초,
조건 비교 후 경유지 지정 26.0초, 진행 상태를 유지한 옵션 변경 36.2초였다.
음성 인식을 포함하지 않으며 첫 작업은 모델 준비 비용을 포함한다. 여러 단계 작업의 10초 목표는 충족하지 못했다.
두 종료 표현은 종료 후 추가 지도 조작 없이 끝났지만, 한 표현은 종료 메뉴 전에 잘못된 후보를 세 번 시도했다.
GPU 검사와 최종 공개 APK의 검사 결과는 릴리즈 `validation.json`, `public-download-validation.json`에 기록한다.
