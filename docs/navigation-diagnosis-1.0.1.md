# 1.0.1 실제 휴대폰 진단과 내비 완료 판정

검증일: 2026-10-09. 클로드 수정본 1.0.0(code 100)을 S25 Ultra에서 가져와 원본 APK와 일치하는지 확인한 뒤, 그 소스를 기준으로 1.0.1(code 101)을 수정했다. 음성 진입 바텀시트와 별도 설정 화면은 유지했다. 현재 선택 모델은 Kanana 1.5 2.1B Q4_K_M이며 기존 GGUF 파일 4개를 삭제하거나 바꾸지 않았다. 이전 0.7 계열의 UI·모델·음성 기록과 구분해서 조사했다.

## 확인한 원인

### 회사 길안내가 음악 정지로 잘못 분류됨

1.0.0의 최근 실행 기록 3개에서 `회사로 안내해 줘` 또는 `회사로 가자`의 입력 목표는 정확했지만 Router가 `Media(PAUSE)`를 선택했다. 실제 결과 문장도 `음악을 멈췄어요.`였다.

새 앱의 로컬 장소 파일에는 회사가 없었다. 분류기는 등록된 장소가 없으면 출력 문법에서 navigate를 제거하면서 media는 남겨 놓았다. 작은 모델이 명령과 관계없는 pause를 선택해도 의미 검증이 없었고, 미디어 키 전송은 무조건 성공을 반환했다. 따라서 인식 문장의 띄어쓰기보다 **명령 분류와 목표 검증**에 문제가 있었다. 이 원본 기록에는 호출 출처가 없으므로 각 기록이 음성인지 텍스트인지까지 단정하지 않는다.

1.0.1은 미등록 길안내를 실제 지도 화면 작업으로 보낸다. 로컬 장소가 있으면 링크를 먼저 사용하는 빠른 경로다. 등록이 없으면 지도에 있는 집·회사·자주 가는 곳, 저장 장소 또는 검색으로 해결을 계속한다. 길안내 목표에서 엉뚱한 음악 키를 고르면 Router와 화면 실행 Guard가 모두 거절한다. `지도 켜줘`는 별도의 앱 실행 명령으로 처리한다.

### 실제 앱과 다른 화면을 반복해서 읽음

수정 중 실제 S25 실행에서 네이버 지도는 전면에 떠 있었지만 접근성 관찰 결과는 이전 요기요 화면이었다. 에이전트는 이전 화면을 보고 지도를 다시 열라고 판단했고, 실행 함수는 지도는 이미 열려 있다고 답하는 모순이 반복됐다. 이 실행은 61.7초 뒤 화면 무변화로 실패했다. 첫 불필요한 모델 판단 하나에 22.6초가 걸렸다.

접근성 서비스가 window-state 이벤트만 구독하고 창/내용 변경을 충분히 반영하지 않아 캐시된 창 트리를 반환하는 문제를 확인했다. 1.0.1은 창·내용·스크롤·텍스트 변경 이벤트를 구독하고, Android 13 이상에서 관찰 및 행동 직전에 캐시를 비운다. 활성/포커스 앱 창을 우선한다. 앱 실행 함수도 launch 호출 성공을 화면 전환 성공으로 취급하지 않고 실제 요청 패키지가 전면에 보일 때까지 기다린다. 수정 후 같은 휴대폰의 회사 길안내가 실제 지도 화면을 사용해 완료됐다.

### 링크 실행과 경로 미리보기를 실제 안내 시작으로 오인함

원본 `AndroidTools.navigate`는 링크를 열고 최대 12초 동안 안내 문구를 기다렸지만, 대기 시간이 끝났을 때 확인 실패를 무시하고 항상 `안내를 시작했어요.`를 반환했다. 도착 예정·남은 거리만으로도 성공을 판단했다. 이 문구는 안내 시작 전 미리보기에도 나타날 수 있다.

Assistant는 반환 문장이 있으면 작업을 DONE으로 끝냈으므로, 링크가 경로 선택 화면까지만 열었거나 안내 버튼을 못 눌러도 화면 조작 fallback이 실행되지 않았다. 버튼 클릭이 시스템에 전달됐다는 결과만으로도 사용자는 실제 안내 시작을 보장받지 못한다.

### 완료 후에도 동작 중처럼 보임

완료 뒤 방법을 기억할지 묻는 오버레이가 최대 20초 동안 남았고, 음성 출력 준비/종료 대기에도 시간 제한이 없었다. 1.0.1은 경로 기억 확인을 설정 화면으로 옮겼다. 실행 결과는 즉시 완료로 표시하고 TTS 대기는 제한한다. 이전 작업의 정리 콜백이 새 작업을 중단하지 않도록 실행 ID도 검증한다.

## 내비 완료는 어떻게 판단하는가

여기서 완료는 **요청한 목적지로 길안내가 시작됨**이다. 목적지에 도착했다는 뜻이 아니다.

명령별 `NavigationSession`을 만들고, 도구 링크와 화면 fallback이 같은 세션을 공유한다.

1. 명령에서 요청한 장소와 별칭을 추출한다. 등록된 좌표는 선택적인 빠른 경로다.
2. 현재 화면의 목적지 항목을 선택하거나 검색한 이력을 보존한다. 다른 목적지가 명시되면 기존 증거를 취소한다. 이전부터 떠 있던 안내는 새 명령의 완료로 인정하지 않는다.
3. `안내시작`이 보이면 미리보기 상태다. 도착 예정·남은 거리·클릭 전달 성공만으로 DONE을 반환하지 않는다.
4. 활성화된 현재 버튼을 누르고 화면을 다시 읽는다. 클릭이 받아들여졌으나 화면이 그대로면 최신 노드를 재검증하고 해당 노드의 실제 위치를 탭한다. 추측 좌표는 사용하지 않는다. 최대 3회 시도한다.
5. 이번 명령의 목적지 증거와 실제 안내 문구가 함께 확인돼야 성공이다. 실기에서는 `경로안내를 시작합니다.`가 확인됐다. 안내 종료·경로 안내 중·주행 중 같은 명확한 상태도 사용한다.
6. 직접 링크 확인이 제한 시간 안에 끝나지 않으면 실패 문장을 꾸며내지 않고 화면 에이전트로 이어간다. 모델이 done을 출력해도 내비 증거가 없으면 거절한다.

화면 요약은 하단 안내 시작 버튼과 목적지/입력 항목이 도로 이름 등으로 밀려 사라지지 않도록 우선순위를 둔다. 현재 화면에서 유일한 회사 항목이나 길찾기 항목은 짧은 규칙으로 선택하고, 후보가 여러 개면 일반 화면 AI가 판단한다. 모호한 목적지를 무조건 첫 항목으로 고르지 않는다.

## 실제 검증 결과

| 명령/검증 | 결과 | 실행 시간/조건 |
|---|---|---|
| 회사로 안내해 줘 | 실제 네이버 지도에서 길찾기 → 회사 → 안내시작 → 실제 안내 화면 확인 | 3,475 ms. 앱 로컬 장소 미등록, 지도는 앞선 조사로 열려 있었음 |
| 지도 켜줘 | 장소 없이 Android API와 전면 앱 확인으로 완료 | 168 ms. 이미 지도가 전면인 상태 |
| 설정에서 와이파이 화면 열어줘 | 공식 Intent로 실제 Wi-Fi 화면 도달 확인 | 570 ms. 값/스위치는 변경하지 않음 |
| JVM 회귀 테스트 | 64개 통과 | 잘못된 Tool, 미리보기/이전 안내/다른 목적지, 무반응 클릭, 버튼 활성화, 다운로드 계약 등 |
| S25 모델·업데이트 APK 검사 | 4개 통과 | 실제 선택 모델 + 모의 지도, APK 패키지/버전/서명, 공유 경로 제한. 총 16.145초 |
| Android 빌드/검사 | release APK 빌드 및 lint 통과 | 기존 설치본과 동일한 서명, versionCode 101 |

실제 내비 테스트는 마이크 입력을 생략한 텍스트 명령을 **앱의 실제 AgentService 실행 경로**로 전달했다. 화면은 실제 네이버 지도였고, 시뮬레이션이 아니었다. 검증용 안내는 종료했다. 가운데 마이크의 실제 발화와 물리적인 뒷면 두 번 호출은 이번 검증에 포함하지 않았다.

별도의 S25 instrumentation은 선택된 실제 모델을 사용하되 지도 화면만 모의로 구성한다. 이 테스트는 모델 추론과 무관한 음악 실행 방지, 완료 판정을 확인하며 실제 길안내 실기와 구분한다. 테스트 실행기가 앱 프로세스를 종료하면 접근성 서비스도 일시적으로 연결을 잃으므로, 테스트 후 동일 배포 APK를 데이터 유지 설치하고 서비스 재연결을 확인한다.

## 10초 목표와 남은 한계

3.5초 내비 결과는 목표를 만족했지만 모든 명령에 10초를 보장하는 결과가 아니다. 명확한 앱 실행/설정 화면 열기, 지도에서 유일한 목적지 선택/안내 시작은 매 단계 모델을 호출할 필요가 없어 빨라졌다. API가 없거나 여러 후보를 비교해야 하는 작업은 로컬 모델 추론을 사용한다.

수정 전 기록에는 화면 판단을 11~13회 반복해 130~149초 걸린 설정 작업이 있었다. 중간 판단뿐 아니라 완료 검증에도 모델을 호출해 지연을 늘렸다. 최종 실제 모델 테스트에서도 콜드 prefill 하나가 10.229초, 생성이 0.711초였으므로, Q4라는 이름만으로 빠른 완료를 보장할 수 없다. 화면 캐시 오류로 재실행하는 루프를 제거하고 명확한 완료에 추가 모델 호출을 없애는 것이 먼저다. 설정의 판단 설명 생성을 끄면 출력 토큰은 줄지만 큰 입력의 prefill 비용은 남는다. 사용자의 모델/설명 설정은 임의로 변경하지 않았다.

현재는 실행 기록에 입력 출처, 원본 ASR 후보/신뢰도, 선택 모델/GPU/스레드, Router 원문, 화면/행동/검증 상태, 실행 시간과 10초 달성 여부, 취소/정리 상태를 남긴다. confidence=0 하나만으로 정확한 음성 명령을 거절하지 않는다. 다음 물리적 음성 호출에서 문제가 재현되면 이 기록으로 입력 문제인지 실행 문제인지 비교할 수 있다. 개인 화면과 장소를 포함하는 원본 기록은 GitHub에 게시하지 않는다.

지도 앱 업데이트로 버튼 이름/트리가 바뀌거나, 위치 획득·네트워크·안내 계산이 늦거나, 목적지가 여러 곳이면 시간이 더 걸릴 수 있다. 로그인/잠금 해제가 필요하면 사용자에게 요청하며 인증 입력은 자동화하지 않는다.

## GitHub 업데이트

음성 비서 설정의 **GitHub 업데이트 확인** 버튼은 공개 latest 릴리즈와 `update-agent.json`을 읽고 새 버전의 `LocalPhoneAgent.apk`를 자동으로 받는다. 전송 크기·SHA-256·APK 실제 패키지/버전/최소 Android 버전과 설치된 앱의 서명이 모두 맞아야 Android 설치 화면을 연다. 최종 설치는 Android에서 확인한다. 모델 파일과 설정은 유지된다.

1.0 계열은 클로드 설치본과 같은 로컬 키로 서명한다. 0.7 계열과 서명이 달라 그 APK를 바로 덮어쓰는 자동 업데이트는 지원하지 않는다. 개인 서명 키와 모델 가중치는 공개 소스에 포함하지 않는다. 배포 APK의 디버그 ADB 명령 입력은 비활성화한다.
