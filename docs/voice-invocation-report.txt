과거 0.3.0 기록입니다. 현재 목표 우선 실행판은 LocalPhoneAgent-automation.apk이며, 최신 내용은 목표 우선 실행과 화면 작업 안내.txt와 automation-verification.json을 참조하세요.

Local Phone Agent 0.3.0 — 음성 호출과 보안폴더 검증 보고
2026-10-07 / 한국 시간 기준

앱 실행 직후 작은 창에서 자동으로 듣고, 로컬 인식·명령 검사·공식 실행 요청을 거쳐 종료하는 개발판입니다.
가상폰에서 JVM 57개 + Android 42개 = 고유 99개가 통과했습니다.
실제 S25 Ultra/Knox/RegiStar/Clipstream/차량 Bluetooth와 FunctionGemma 추론은 실행하지 않았습니다.
보안폴더 설치 공간을 존중하는 구현과 Samsung Knox에서의 실제 동작 검증을 구분합니다.

보안폴더에 설치하는 방법
APK를 설치하고 보안폴더 → 앱 추가에서 Local Phone Agent를 추가합니다.
지도·음악 등 대상 앱도 보안폴더에 추가합니다. 그 안의 Agent에서 마이크 권한·음악 연결·장소·모델을 따로 준비합니다.
기존 일반 영역의 설정·DB·계정·모델은 자동 복사하지 않습니다. 복사본마다 별도 저장소와 권한을 사용합니다.
앱·알람·타이머·설정 처리 앱의 UID도 현재 UserHandle로 확인하고 확정 Activity에만 요청합니다.
플랫폼 chooser/프로필 forwarder나 다른 영역의 앱으로 전달하지 않으며 처리 앱을 확정하지 못하면 차단합니다.
RegiStar의 뒷면 두 번 탭 → 앱 실행 설정은 사용자 수동 작업입니다.
RegiStar가 보안폴더 안의 복사본을 선택/실행할 수 있는지는 현재 연결 기기에서 확인할 수 없습니다.
보안폴더를 잠근 상태에서 호출이 막히면 우회하지 않습니다. 앱까지 호출이 전달되면 AUTH_REQUIRED로 처리합니다.
보안폴더의 알림 접근 제한 때문에 현재 음악 제어가 막힐 수 있습니다. 일반 영역의 음악 앱으로 대신 연결하지 않습니다.
삼성의 2021년 보안폴더 담당 답변은 Android 10부터 알림 접근 미지원을 안내합니다. S25 최신 버전의 지원 여부는 아직 검증하지 않았습니다.

앱 복사본과 설치 안내: https://www.samsung.com/uk/support/mobile-devices/what-is-the-secure-folder-and-how-do-i-use-it/

1. Voice Invocation architecture
VoiceInvocationActivity → VoiceSessionCoordinator → SpeechInput → AgentEngine
→ FunctionGemma 또는 명시된 기본 테스트 문법 → ToolPlan → PolicyGate → Android runtime.
Activity는 작은 UI와 lifecycle만 담당합니다. 지도/미디어별 로직은 runtime에 둡니다.
sessionId와 Application의 active lease, 상태 전이, speech callback token으로 중복과 늦은 결과를 차단합니다.
IDLE/STARTING/LISTENING/TRANSCRIBING/PLANNING/POLICY_CHECK/EXECUTING/SUCCESS 및 개별 실패 상태를 구분합니다.
모호한 장소는 후보 이름을 정확히 말하는 1회 재질문만 허용합니다. 다시 모호하면 실행하지 않습니다.

3. Microphone 시작 방식
최초 설명·권한 승인 후 기본 런처는 마이크 버튼 없이 자동 시작합니다.
최초 onboarding 자동 검사는 마이크 권한을 미리 허용한 AVD에서 설명 화면→자동 시작을 확인했습니다. 실제 시스템 권한 승인 대화상자는 실기 확인 항목입니다.
AudioRecord VOICE_RECOGNITION / 16 kHz / mono PCM16을 캡처 전용 스레드에서 즉시 시작합니다.
STT 디코더 및 Agent model 로딩은 캡처와 병렬입니다. 초기 PCM은 제한된 메모리 큐에 보관합니다.
입력과 큐 초과는 오류로 종료합니다. 마이크 준비 callback에서만 준비 진동을 냅니다.
기본 최대 음성 18초, 시작 대기 4.5초, 말 끝 무음 0.9초는 설정 가능한 초기값입니다.
한국어/차량 튜닝을 마친 수치라고 표시하지 않습니다. Back/×/앱 이탈은 즉시 캡처를 취소합니다.

4. 사용한 Local STT
APK에 sherpa-onnx 1.12.20 + sherpa-onnx-streaming-zipformer-korean-2024-06-16을 포함했습니다.
CPU local ONNX 경로입니다. assets에서 모델을 읽고 원본 녹음 파일을 만들지 않습니다.
플랫폼 SpeechRecognizer는 한국어/비행기 모드를 직접 검증한 뒤 설정에서 선택할 때만 명시적 on-device API를 사용합니다.
실제 S25 제공자의 한국어/offline 지원이 검증됐다고 가정하지 않습니다.
모델 revision·파일 SHA-256·출처·라이선스는 speech-model.json과 APK assets/licenses에 있습니다.
공식 모델: https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-transducer/zipformer-transducer-models.html#sherpa-onnx-streaming-zipformer-korean-2024-06-16-korean

5. 실제 offline 검증 방법
전용 AVD의 cmd connectivity airplane-mode enable 및 airplane_mode_on=1을 확인했습니다.
Microsoft Heami로 만든 한국어 PCM WAV를 실제 Android sherpa-onnx 디코더에 공급했습니다.
인식: '오전 7시 알람 맞춰 줘' → 기본 테스트 문법 → policy → 실제 Google Clock에 7시 0분 요청.
자동 런처 cold/warm 2회와 기존 수동 화면의 offline 경로를 검사했습니다.
별도 실제 AudioRecord의 무음 입력도 준비·자동 NO_SPEECH 종료·미실행을 확인했습니다.
실제 사람의 발음·차량 잡음 정확도나 FunctionGemma의 offline 추론을 검증한 결과는 아닙니다.
기록: emulator-test/emulator-evidence/invocation-offline-cold-warm.json 및 offline-speech-result.txt.

6. Cold / Warm latency
Android 15 x86_64 / WHPX / 4 GB 전용 AVD, 다음 각 1회 표본입니다.
합성 PCM cold: mic ready 73 ms / STT load 1662 ms / capture 종료→STT 1961 ms / plan 1 ms / 실행 요청 12 ms / 총 2085 ms
합성 PCM warm: mic ready 57 ms / STT load 0 ms / capture 종료→STT 288 ms / plan 1 ms / 실행 요청 12 ms / 총 370 ms
실제 AudioRecord 무음 cold: mic ready 81 ms / STT load 1453 ms / NO_SPEECH 총 5082 ms.
합성 PCM은 실제 시간으로 말하는 속도로 재생하지 않고 빨리 메모리에 공급합니다. 따라서 이 수치는 연산 비용 관찰이며 사람 발화 latency와 동일하지 않습니다.
T0은 앱 Activity 생성 진입 시각 근사, T1은 window focus, T2는 실제 마이크 준비 시각,
T3는 PCM 에너지 시작 추정, T4는 캡처 종료, T5는 최종 STT, T6는 계획 완료, T7/T8은 실행 요청 시작/끝입니다.
T0 이전 RegiStar 센서 감지 지연과 실제 발화 종료 정답 시각은 측정하지 않았습니다.
STT는 사용 후 60초 idle 캐시 해제를 구현했습니다. 실제 S25 RAM/배터리 최적값은 미확정입니다.

7. FunctionGemma load/inference latency
모델 파일이 없어 미측정입니다. 0 ms나 AI PASS로 표시하지 않습니다.
AI 모드이면 듣는 동안 준비를 시작하고 STT 이후 같은 엔진을 사용합니다. 모델 실패는 MODEL_UNAVAILABLE로 차단합니다.
LiteRT-LM의 자동 도구 실행을 끄고 모델 결과를 schema/grounding/policy로 검사합니다.
메모리/배터리 자료가 없어 FunctionGemma의 장기 warm 유지와 상주 서비스는 적용하지 않았습니다.
세션 종료 시 해제합니다. model load/inference 측정 필드는 debug trace에 있습니다.

8. Audio Focus 처리
보이는 Activity에서 AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK 요청 후 마이크를 시작합니다.
focus 거부 시 마이크를 시작하지 않고 실패합니다. focus 상실은 세션을 취소합니다.
캡처가 종료되면 focus를 반납합니다. 복원을 위한 transport play/pause는 보내지 않습니다.
따라서 '노래 멈춰' pause 이후 종료 과정에서 임의 resume을 보내지 않습니다.
실제 AudioManager의 LOSS_TRANSIENT_CAN_DUCK/Gain callback과 pause 1회/resume 0회를 검사했습니다.
자동 duck의 실제 음향 크기, Clipstream 반응, 내비 음성/Bluetooth 환경은 미검증입니다.
공식 문서: https://developer.android.com/media/optimize/audio-focus

9. Previous-app 복귀
VoiceInvocationActivity는 singleTask + 별도 voice affinity + excludeFromRecents=true입니다.
onboarding 결과 수신을 위해 noHistory=false를 사용하고 이탈/완료 시 직접 종료합니다.
배경 pause/next는 대상 앱을 열지 않고 voice root task만 제거하여 기존 지도 화면으로 복귀합니다.
지도/기기 화면 Intent에는 NEW_TASK를 지정해 새 대상 화면이 voice task 제거로 사라지지 않게 합니다.
지도에는 SINGLE_TOP도 지정합니다. NEW_TASK만 사용할 때 기존 작업을 앞으로 가져오며 새 목적지가 전달되지 않던 경우를 검사가 찾아 수정했습니다.
기존 지도 목적지 'PreviousMap' 유지와 새로운 집 지도 전면을 각각 가상폰에서 검증했습니다.
이전 앱 목록을 수집하는 UsageStats/Accessibility/다른 사용자 실행 API는 없습니다.
근거: https://developer.android.com/guide/components/activities/tasks-and-back-stack
https://developer.android.com/guide/topics/manifest/activity-element

10. Screen lock 상태 테스트
AVD 화면을 실제 sleep 상태로 만든 뒤 일반 launcher 호출을 전달했습니다.
AUTH_REQUIRED로 종료하며 마이크 start 0회를 확인했습니다.
현재 사용자 isUserUnlocked/isDeviceLocked, 전역 keyguard, interactive 상태를 시작·실행 직전에 검사합니다.
showWhenLocked/turnScreenOn/requestDismissKeyguard/컨테이너 unlock 우회를 구현하지 않습니다.
RegiStar가 S25 screen-off/잠금 상태에서 Intent를 전달할 수 있는지는 별도 미검증입니다.
근거: https://developer.android.com/reference/android/app/KeyguardManager#isDeviceLocked()

11. 실제 S25 Ultra Back Tap 결과
NOT_RUN. adb에 연결된 기기는 emulator-5554뿐이었습니다.
실제 RegiStar 호출 Intent 형태·보안폴더 대상 선택·준비 진동·한국어 인식·센서→T0 latency를 확인하지 못했습니다.
RegiStar 설정 자동화나 성공한 물리 뒷면 탭처럼 보이는 결과를 만들지 않았습니다.

Test B next: 실제 차량 NOT_RUN / 가상폰 skip 한 번 및 창 종료 PASS.

13. 개인정보 외부 전송 경로
캡처 PCM·STT 최종 문장·Agent model input·개인 장소 DB·debug trace를 외부 AI 서버로 보내는 코드는 없습니다.
외부 telemetry/analytics SDK/클라우드 STT/클라우드 TTS를 사용하지 않습니다.
기본 녹음 파일은 없으며 bounded PCM은 세션 후 버립니다. Debug 마지막 trace 1개는 Keystore AES-GCM 설정으로 암호화합니다.
Debug 화면은 내부 Activity이며 자동 호출에서 열리지 않습니다. 앱 화면은 FLAG_SECURE이고 백업/기기 전송은 제외합니다.
연락처·메시지·알림 본문을 읽는 도구/권한은 현재 구현하지 않았습니다. 알림 listener는 재생 세션 접근용입니다.
예외로 사용자가 설정한 네이버 지역 검색 API에는 공개 장소 검색어·API 인증 정보가 전송됩니다.
네이버 지도 Intent에는 실행할 목적지 이름/좌표를 넘깁니다. 지도·음악의 정상 서비스 통신은 대상 앱이 담당합니다.
지역 검색 외부 통신은 NaverPlaceSearch.kt의 HTTPS 1개 경로이며 개인 home 등 슬롯은 외부 검색으로 넘기지 않습니다.
이는 소스 경로 조사와 offline STT 실행 결과입니다. 모든 제3자 바이너리/지도/음악 앱의 네트워크 포렌식을 수행한 것은 아닙니다.

14. 남은 blocker
- 실제 S25/보안폴더/RegiStar/차량 기기가 없어 물리 호출과 설치 공간의 공식 연동을 확인할 수 없습니다.
- 보안폴더에서 알림 listener가 차단되면 현재 MediaSession 방식으로 Clipstream을 제어할 수 없습니다.
  Android 공식 문서도 work profile의 NotificationListener를 system이 무시한다고 설명합니다.
  표준 managed profile 추가 저장소 결과: PASS_STANDARD_ANDROID_PROFILE_STORAGE_ONLY.
  별도 /data/user/프로필/ 설치 경로를 확인하고 일반 영역의 설정 파일이 없음을 확인했습니다. 프로필의 Room/Keystore 검사를 실행해도 일반 영역 설정 hash는 같았고 임시 프로필은 제거했습니다.
  Room/Keystore 추가 2회는 반복 사례라 고유 테스트 합계에 더하지 않습니다. Samsung Knox 시험으로 해석하지 않습니다.
- 호환 FunctionGemma 가중치와 한국어 도구 규약의 실제 모델 추론 검증이 필요합니다.
- Clipstream의 현재 곡 저장 공식 인터페이스가 확인되지 않았습니다.
- 실제 사람 음성·차량 소음·Bluetooth·배터리와 RAM 튜닝 자료가 없습니다.
NotificationListener 문서: https://developer.android.com/reference/android/service/notification/NotificationListenerService

15. 다음 ONE AXIS 개선 제안
S25 보안폴더에서 '호출과 공식 앱 제어 접근성' 한 축을 먼저 확정합니다.
Agent/대상 앱을 보안폴더에 추가 → RegiStar가 해당 복사본을 호출하는지 확인 → mic/lock 확인

이 한 축이 확정되기 전에는 기능 수를 늘리거나 별도 영역의 앱/보안 우회로 성공 상태를 만들지 않습니다.
