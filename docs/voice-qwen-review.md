# Local Phone Agent 0.7.1 — 음성 연결·Qwen·작업 완료 검토

검증 대상: **0.7.1-automation / versionCode 10**, APK SHA-256 `a64d817958a95a630098d7c01d6148749a051c7c0bf48a1f8f4d3c5e9fcaf6b4`. Android 15/API35 x86_64 전용 AVD, CPU 4 threads. S25에서의 실제 뒷면 두 번 두드리기·실제 NAVER는 미검증이다. 가상폰 런처 시험을 실제 RegiStar 검증으로 표시하지 않는다.

사용자는 일반 영역의 앱에서 Q4 중앙 음성·텍스트는 동작하고 뒷면 호출은 동작하지 않는다고 확인했다. 별도 보안폴더 모델 선택 문제로 단정하지 않았다. 자동 호출에서 최종 인식 뒤 다른 화면이 잠깐 덮이면 onStop이 명령을 취소하던 경로를 수정했다. 실제 OS에서 PLANNING 중 Settings를 열어 Activity를 중지한 뒤 실제 Qwen 계획·목적지 탐색·안내까지 이어지는지 검사했다. 호출 창의 AI 이름, 설치 버전/공간, 진입점, 단계, 전화/화면 모델 추론과 오류를 기록하며 이전 세션의 모델 응답을 새 호출 응답으로 표시하지 않는다.

## 완료 동작

전체 화면 작업의 45초 제한이 모델 추론과 앱 조작을 함께 중단할 수 있었다. 전체 제한은 180초, 개별 Qwen 전화 추론 45초·UI 추론 30초이며 28개 조작과 반복·취소·잠금 제한은 유지한다. 카운트다운 숫자가 붙은 안내 시작·비활성 버튼·늦게 나오는 버튼은 새 관측으로 처리한다. 제공자 자동 카운트다운은 관측했던 경로와 현재 목적지 및 안내 상태가 맞아야 성공한다. 누른 뒤 실제 안내가 없거나 다른 목적지이면 성공/캐시로 처리하지 않는다.

실제 모델이 조작 불가능한 완료 텍스트를 계속 누르려 하던 경로도 현재 노드의 capabilities/활성 상태로 제한했다. 두 화면을 조작해 새 완료 표시를 관측하고 `ui_complete`를 생성하는 실제 Qwen·OS 접근성 시험이 통과했다. 이 일반 UI 입력의 초기 전화 모델 제안은 `open_app`이어서 grounding이 거부했다. 원래 목표 fallback 뒤 실제 Qwen UI가 완료했으며 전화 모델 성공으로 바꾸어 표시하지 않는다.

## 10초 목표와 실제 시간

기준은 **음성 최종 인식(T5)부터 완료(T8)**이다. Clock은 공식 Android 요청/foreground 전달, 내비는 별도 테스트 앱의 실제 안내 상태를 관측한 시점이다. 음성 캡처·STT 자체 시간은 이 목표에 포함하지 않는다.

| 시험 | 인식 후 완료 ms | 결과 |
|---|---:|---|
| 자동 음성 → 실제 AVD Clock 요청 | 6834 | SUCCESS |
| 중앙 음성 → 실제 AVD Clock 요청 | 8275 | SUCCESS |
| 최초 회사 탐색 + 명령 해석 중 일시 화면 덮임 | 9096 | SUCCESS |
| 같은 회사 재호출 + 관측한 안내 시작 | 7422 | SUCCESS |
| Qwen으로 두 화면 조작·새 완료 표시 확인 | 40802 | SUCCESS |

**모든 작업이 10초 이내인 상태는 아니다.** 여러 모델 UI 단계는 목표를 넘는다. 위 시간은 각 입력의 최종 파일 1회 측정이며 다양한 발화·앱·콜드 시작의 지연 분포를 보장하지 않는다. 개발 후보의 같은 최초 장소 탐색은 약 10.9초였고 최종 측정값과 합산하지 않았다. 자연 발화/차량 평가를 사용자가 생략하기로 했으므로 Clock 음성은 합성 한국어 PCM을 실제 포함 STT decoder로 인식한 결과다. 내비·범용 화면 목표의 음성은 STT callback fixture이고 실제 모델/OS 조작이다. S25의 native STT·RegiStar·NAVER 지연 또는 자연 발화 정확도로 일반화하지 않는다.

## Qwen 개선과 검증

같은 Tool 의미를 유지한 compact prompt, 전화 입력 prefill 재사용, 화면 간 고정 UI system prefix, 완료 JSON의 조기 종료, native 취소/시간 제한을 적용했다. 최초 실제 건강검사가 통과한 공통 Tool 입력의 계산 상태만 답변 생성 전에 private noBackup에 저장한다. 사용자 명령/화면/답변은 저장하지 않는다. 재사용은 모델·빌드·ABI·입력·런타임·크기·SHA 및 native token을 검사한다. 명령은 매번 새 실제 native 생성이다. 모델을 내린 후 복원, 새 알람 생성, 사용자 추론 뒤 입력 파일 불변, 손상 시 실제 재준비, 기한 초과·시작 전 취소·새 추론 복구가 통과했다.

복원 시 모델 준비: `{'extractionMs': 7, 'inputPrefixRestored': True, 'modelId': 'qwen3', 'nativeLoadMs': 327, 'probeMs': 0}`. 고정 입력 상태 크기 **43,129,421 bytes**. 자동 복원에는 새 health 답변을 생성하지 않았으므로 probe 0을 새 추론으로 표시하지 않는다. 명시적 모델 전환은 새 실제 health probe를 실행한다. 메모리는 선택 모델 하나, 기존 30초 idle 해제를 유지한다.
